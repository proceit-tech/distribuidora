# AUTH-ADMIN — Mapeamento campo a campo: autenticação, sessão, shell e menu (módulo AUT)

- **Módulo:** Autenticação, sessão, shell (sidebar/empresa/usuário exibidos) e menu de navegação com permissões. Prefixo de ID: `AUT`.
- **Telas:** `/login` (formulário Empresa fixa, Usuario, Contraseña); shell privado (sidebar com cartão de empresa e de usuário, botão Cerrar sesión); menu de 8 grupos e 32 itens. Telas administrativas (`/administracion/usuarios|roles|configuracion|auditoria`) estão no menu mas **não existem** no código.
- **Status do módulo:** **PARCIAL** — login, sessão e logout têm SQL real (PostgreSQL via `pg`) e um modo DEMO; menu, papéis e permissões efetivas são DEMONSTRATIVOS (permissões nunca carregadas); administração de usuários/perfis/auditoria é PROPOSTO (REQ-2026-002).
- **Código analisado:** `0dbb013` (worktree `docs/REQ-2026-003-mapeamento-banco`; diff de `app lib components types` contra `0dbb013` é vazio). Toda coluna SQL é **CONFIRMADO_CODIGO** (o código a usa); nada foi VERIFICADO_BANCO.
- **Convenção:** tabelas/colunas da coluna *Atual* são as em espanhol que o SQL usa; *Alvo* é proposta em inglês (nada foi renomeado). Tipos de `id` NAO_VERIFICADOS.

## Regras confirmadas no código

1. Login é por (código da empresa, usuário, senha); empresa e usuário são normalizados com trim e minúsculas; senha não. — `app/api/auth/login/route.ts:67-80`
2. Limites de entrada: empresa ≤ 30, usuário ≤ 80, senha ≤ 200; qualquer campo vazio → 400. — `app/api/auth/login/route.ts:82-94`
3. Falha de qualquer tipo (usuário inexistente, bloqueado, senha errada) devolve a mesma mensagem 401 "Usuario o contraseña incorrectos.". — `app/api/auth/login/route.ts:165-169,207-211`
4. Só autentica usuário com `estado='ACTIVO'` em empresa com `activo` verdadeiro. — `app/api/auth/login/route.ts:128-135`
5. Usuário com `bloqueado_hasta` futuro é recusado e gera evento `LOGIN_FALLIDO` com `motivo=USUARIO_BLOQUEADO`. — `app/api/auth/login/route.ts:143-169`
6. Senha verificada no banco por `crypt()` (pgcrypto) contra `password_hash`. — `app/api/auth/login/route.ts:172-175`
7. Senha errada incrementa `intentos_fallidos`; ao atingir 5 bloqueia por 15 minutos; grava evento `LOGIN_FALLIDO` com `motivo=CREDENCIAL_INVALIDA`. — `app/api/auth/login/route.ts:181-205`
8. Login com sucesso (uma transação): zera tentativas e bloqueio, grava `ultimo_acceso_at`, insere sessão (8 h) e evento `LOGIN_EXITOSO`; rollback em erro. — `app/api/auth/login/route.ts:213-264`
9. Sessão = UUID + segredo aleatório de 32 bytes; no banco só o hash bcrypt (custo 12) do segredo. — `lib/auth/session.ts:40-45; app/api/auth/login/route.ts:237`
10. Cookie httpOnly, sameSite lax, path /, secure em produção, validade 8 h. — `app/api/auth/login/route.ts:38-49`
11. IP vem do primeiro valor de `x-forwarded-for` se for IP válido; user agent truncado em 500. — `app/api/auth/login/route.ts:25-36`
12. Sessão válida exige: não revogada, não expirada, segredo confere, usuário `ACTIVO` e não bloqueado. — `lib/auth/session.ts:118-123`
13. Perfis da sessão = códigos distintos dos perfis ativos do usuário. — `lib/auth/session.ts:113-117`
14. Logout revoga a sessão (`revocada_at = now()`) só se id e segredo conferem e limpa o cookie; sempre responde ok. — `app/api/auth/logout/route.ts:35-57`
15. Sem sessão, páginas privadas e `/` redirecionam para `/login`; com sessão, `/login` redireciona para `/dashboard`. — `app/(private)/layout.tsx:11-15; app/(public)/login/page.tsx:7; app/page.tsx:6-12`
16. Em `DEMO_MODE=true` o login aceita só `casa_mingo`/`admin`/`admin123` e a sessão é o cookie fixo. — `app/api/auth/login/route.ts:96-125; lib/auth/session.ts:92-98`
17. `userHasPermission`: permitido se algum perfil ativo do usuário é administrador ou tem (recurso, acción); em demo sempre true. — `lib/auth/permissions.ts:10-27`
18. Menu: 8 grupos e 32 itens, cada item com uma permissão `X.VER`; item exibido se a lista de permissões está vazia ou contém o código; grupo sem itens some. — `lib/navigation/menu.ts:6-337`
