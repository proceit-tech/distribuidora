## Hallazgos que debe corregir Claude

### F-001 — ALTA — Race condition: un JSON tardío sobreescribe la selección más reciente

**Archivo:** `app/(private)/documentos/page.tsx:245–254`, `verJson`.

**Secuencia reproducible conceptualmente:** operador pulsa `Ver JSON de solicitud` versión 1 (A) y enseguida `Ver JSON de respuesta` intento B (o versión 2). Ambas peticiones están activas; B responde primero y se muestra correctamente; después llega A. `actualizarDetalle(d.id, {json: ...vistaA...})` reemplaza contenido B por A, **aunque B era la última selección**. El mismo error ocurre si A devuelve un error tardío. No hay `AbortController`, identificador monotónico ni comprobación de vigencia al resolver.

**Riesgo:** asociación visual incorrecta de evidencia fiscal con selección/versión/intento; afecta integridad de consulta auditada. El backend sí devuelve los registros correctos, pero la UI puede mostrar el elemento equivocado.

**Corrección mínima obligatoria:** invalidar o cancelar la petición previa por documento al seleccionar otra vista; solo la selección vigente puede actualizar el estado de ese documento, tanto en éxito como error. No reutilizar datos tardíos y no modificar endpoints SQL. No alterar lógica de emitir/consultar SIFEN ni la tabla de intentos.

### F-002 — MEDIA — La petición pendiente reabre el JSON/panel cerrado

**Archivo:** `app/(private)/documentos/page.tsx:223–254`, `alternar`, `verJson`, botón `Cerrar JSON` en `:526`.

**Secuencia:** operador inicia `Ver JSON...` y pulsa `Cerrar JSON` antes de resolver la petición; cuando retorna, `actualizarDetalle` repone `json` (el cierre deja de ser efectivo). Si colapsa la fila antes de resolver, `actualizarDetalle` recrea `abiertos[d.id]`, reabriendo el detalle. El helper existente `actualizarDetalle` hace `{...a, [id]: ...}` aunque la fila ya fue cerrada.

**Corrección mínima obligatoria:** al cerrar vista JSON o colapsar detalle, invalidar petición JSON pendiente; respuesta tardía no puede reabrir ni reponer contenido. Mantener otros flujos existentes de Documentos (consulta, envío, KuDE) sin refactor fuera de E01; no empezar E02.
