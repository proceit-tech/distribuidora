## E02-F001 — ALTA — La primera página tardía sigue recreando el detalle cerrado

**Archivo:** `app/(private)/documentos/page.tsx:227–229,273–290`.

**Secuencia:** pulsar `Ver detalle` abre el panel y ejecuta el GET `/api/documentos/[id]` (**primera página paginada**). Mientras `cargando` es true, pulsar `Ocultar detalle` incrementa `historialVigente` y elimina el elemento de `abiertos`. Si el GET inicial responde luego, `alternar` invoca `actualizarDetalle(d.id, ...)` **sin comprobar generación ni que el panel sigue abierto**. El helper crea `a[id]` aun cuando no existía: el detalle reaparece. También una respuesta antigua de una primera apertura puede reemplazar la primera página de una nueva apertura del mismo documento.

**Impacto:** anula el cierre voluntario, puede sustituir cursor/solicitudes/intentros visibles por la primera página desactualizada, contradiciendo la obligación E02 de descartar páginas tardías.

**Corrección mínima:** al iniciar el GET inicial capturar y comprobar la generación vigente de `historialVigente` y la existencia de la misma apertura; invalidar también la carga inicial al colapsar (ya existe el incremento en cierre). En éxito y error usar `setAbiertos` guardado en vez de `actualizarDetalle` que recrea entradas. Preservar el control de JSON E01-R02 y no alterar la lógica de emitir/consultar.

## E02-F002 — MEDIA — Regex de cursor no valida calendario antes del cast PostgreSQL

**Archivo:** `lib/facturacion/shared.ts:218–219,285–296`.

**Secuencia:** un usuario autorizado llama GET `/api/documentos/[id]/intentos?cursor=2026-99-99T99:99:99.999999Z|00000000-0000-0000-0000-000000000001`. El valor **sí pasa** `CURSOR_FORMA`, pero `$3::timestamptz` no admite la fecha/hora imposible. `respuestaErrorFacturacion` no normaliza ese error SQL a 400: se obtiene HTTP 500 y error interno registrado. El contrato establece cursor inválido → 400, no error servidor.

**Corrección mínima:** validar también rango/fecha calendaria/hora del timestamp antes de enviar al SQL, conservando íntegros los seis decimales (no redondear microsegundos al convertir a Date JS); alternativamente reconocer estrictamente códigos PostgreSQL de timestamp inválido para devolver 400 sin exponer detalles. No interpolar valores de usuario en SQL, preservar query parametrizada y formato cursor.
